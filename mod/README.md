# String machine on MOD Audio

This folder holds what is needed to run the three String machine plugins on
[MOD Audio](https://mod.audio) systems: MOD Dwarf, MOD Duo X, and mod-audio
(mod-host + mod-ui) running on a Raspberry Pi 5 or any other Linux board.

| Plugin | URI | Bundle |
| --- | --- | --- |
| String machine (synth, MIDI in, stereo out) | `http://jpcima.sdf1.org/lv2/string-machine-mk2` | `string-machine.lv2` |
| String machine chorus (mono in, stereo out) | `http://jpcima.sdf1.org/lv2/string-machine-chorus` | `string-machine-chorus.lv2` |
| String machine stereo chorus | `http://jpcima.sdf1.org/lv2/string-machine-chorus-stereo` | `string-machine-chorus-stereo.lv2` |

The URIs are the upstream ones, so existing pedalboards and the presets keep
working.

## What a MOD bundle contains

MOD devices are headless: the plugin UI is a web page (the *modgui*) shown by
mod-ui in the browser. A MOD bundle is therefore:

- a **DSP-only** LV2 binary (built with `DISTRHO_PLUGIN_HAS_UI=0`, no Cairo,
  X11 or OpenGL dependency);
- the `.ttl` files generated by DPF (ports, 19 factory presets for the synth);
- `modgui.ttl` + a `modgui/` folder with the HTML template, stylesheet,
  script, images, font, screenshot and thumbnail.

The modgui reuses the skin of the desktop UI (knobs, slider, VU meters, LEDs,
switches and the Proggy font). The synth GUI also draws the AHDSR envelope and
shows the monitored output ports: LFO lights, output VU meters and the live
oscillator detune.

## Layout

```
mod/
  modgui/common/          skin shared by the three GUIs (CSS, images, font)
  modgui/<plugin>/        modgui.ttl + modgui/ (HTML, CSS, JS, screenshot, thumbnail)
  ttl/<plugin>.lv2/       generated .ttl files, used by cross builds
  mod-plugin-builder/     mod-plugin-builder package (string-machine.mk)
  tools/make-skins.py     desktop skins -> horizontal 2x filmstrips (Pillow)
  tools/modgui-preview.py renders a modgui, writes screenshot + thumbnail
```

## Make targets (top-level Makefile)

| Target | What it does |
| --- | --- |
| `make mod` | builds the three bundles in `bin/mod/` |
| `make install-mod` | `make mod` + copy the bundles to `$(MOD_LV2DIR)` (default `~/.lv2`) |
| `make uninstall-mod` | removes them from `$(MOD_LV2DIR)` |
| `make mod-ttl` | refreshes `mod/ttl/` from a native build (commit the result) |
| `make mod-screenshots` | regenerates the modgui screenshots/thumbnails |
| `make clean-mod` | removes `build/mod` and `bin/mod` |

Useful variables: `MOD_LV2DIR`, `MOD_PLUGINS` (subset of the plugins),
`MOD_CPU_FLAGS` (extra compiler flags), `CROSS_COMPILING=true`.

The MOD build uses its own object directory (`build/mod/`), so it never mixes
with the desktop build (`make`, which still produces the LV2/VST plugins with
the Cairo UI).

## 1. Native build on a Raspberry Pi 5 (no mod-plugin-builder)

On the Pi itself (Raspberry Pi OS / Debian with mod-host + mod-ui installed):

```sh
sudo apt install git build-essential pkg-config
git clone --recursive -b mod https://github.com/pilali/string-machine.git
cd string-machine
make mod -j4
make install-mod                       # -> ~/.lv2
```

Then restart mod-ui (or the whole mod-audio service) so that it rescans the
plugins.

- No graphics library is needed: the MOD build does not compile DPF's UI.
- On ARM64 the build adds `-mcpu=native` (Cortex-A76 tuning on a Pi 5). Use
  `make mod MOD_CPU_FLAGS=` for a generic ARMv8 binary that can be copied to
  other boards.
- Install where *your* mod-host looks for plugins, i.e. a folder of the
  `LV2_PATH` used by the mod-host/mod-ui services (check their systemd unit
  or launch script), e.g. `sudo make install-mod MOD_LV2DIR=/usr/local/lib/lv2`.
- The `.ttl` files are generated on the Pi by running DPF's generator on the
  binary; the build warns if they differ from the committed `mod/ttl/`.

## 2. MOD Dwarf / MOD Duo X with mod-plugin-builder

Copy the package into mod-plugin-builder and build:

```sh
cp -r mod/mod-plugin-builder/string-machine ~/mod-plugin-builder/plugins/package/
cd ~/mod-plugin-builder
./build moddwarf-new string-machine     # MOD Dwarf
./build modduox-new  string-machine     # MOD Duo X
```

The bundles are written to `~/mod-workdir/<platform>/plugins/`. Copy them to
the device (`scp -r ... root@192.168.51.1:/root/.lv2/` then restart mod-ui,
or use `./build <platform> string-machine-publish`).

`STRING_MACHINE_VERSION` in `string-machine.mk` selects the commit to build:
pin it to a commit SHA of the `mod` branch (buildroot caches the download by
version, so a branch name would not be refetched).

The package simply runs `make mod CROSS_COMPILING=true` with the toolchain
environment of mod-plugin-builder, then `make install-mod`. When cross
compiling the plugins cannot be executed to generate their `.ttl`, so the
committed copies in `mod/ttl/` are used; keep them in sync with
`make mod-ttl` whenever ports, presets or metadata change.

Without mod-plugin-builder's `build` script, the same cross build can be done
from its environment:

```sh
source ~/mod-plugin-builder/local.env moddwarf-new
make mod CROSS_COMPILING=true
```

## Updating the modgui

- Edit `mod/modgui/common/skin.css` (shared) or the files under
  `mod/modgui/<plugin>/modgui/`. The stylesheet published in the bundle is
  `skin.css` followed by the plugin's own stylesheet.
- `{{{cns}}}` / `{{{ns}}}` are substituted by mod-ui (per-plugin CSS namespace
  and resource query string); resources are referenced as
  `url(/resources/<path inside modgui/>{{{ns}}})`.
- Run `make mod-screenshots` (Pillow + Chromium + jQuery from a mod-ui
  checkout) to refresh the screenshot and thumbnail.

## Performance notes

Measured on an x86-64 desktop (3.5 GHz) at 48 kHz, 128-frame blocks: about
2 % of a core for the engine and BBD chorus, plus about 0.45 % per sounding
voice (16 voices: about 9 %). The digital chorus model costs about 25 % less
than the analog BBD one; note that the BBD chorus keeps running when the
chorus is switched off.

The MOD Dwarf (Cortex-A35) is several times slower per core than such a
desktop: on the Dwarf, lower the *Polyphony* parameter (default 16) and/or use
the digital chorus if the CPU meter of mod-ui runs high. The Duo X and the
Raspberry Pi 5 have much more headroom.

The synth peaks above 0 dBFS when many voices play with the default master
gain (+3 dB); lower *Output* if the hardware output clips.
